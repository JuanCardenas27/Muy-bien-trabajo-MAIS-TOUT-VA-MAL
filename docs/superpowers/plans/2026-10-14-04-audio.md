# Audio: TTS por lotes y clonación -- Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Lee `AGENTS.md` antes de tomar una tarea.

**Goal:** Pre-generar por lotes, cachear por hash y registrar en el Store el audio de cada tarjeta: 13 voces Edge-TTS a diario (Azure TTS F0 como respaldo con tope) y voces adolescentes/infantiles por clonación semanal con QA automática.

**Architecture:** `frances.audio` decide qué clips hacen falta (`plan_audio` → filas `audio` en `pending` + enlaces `card_audio`) y la etapa `run_audio` sintetiza solo la familia `ms-neural`, post-procesa con ffmpeg y escribe `audio/<key>.mp3`. El proyecto aislado `clone/` (`frances-clone`, Python 3.11, torch) consume las filas `pending` de las familias `chatterbox`/`xtts` en un runner self-hosted, valida cada clip con faster-whisper (CER) y reutiliza `frances.audio.post` y `frances.audio.repo`.

**Tech Stack:** Python 3.11–3.13, edge-tts (versión de ADR-001), httpx, PyYAML, asyncio, ffmpeg/ffprobe por subprocess · `clone/`: Python 3.11, Chatterbox Multilingual, coqui-tts (XTTS v2), faster-whisper, praat-parselmouth, soundfile, rapidfuzz, Typer.

**Spec:** `docs/superpowers/specs/2026-10-14-frances-classroom-design.md` (G4, D6, D7, D8, §6.5, §7)

Plan maestro: docs/superpowers/plans/2026-10-14-00-master-plan.md (Global Constraints y contratos aplican a todas las tareas)

## Restricciones del subsistema

- Nunca síntesis en runtime: ni la SPA ni ninguna etapa del bundle sintetizan. Lo que falta queda `pending` y la app lo muestra como «audio pendiente».
- La licencia CPML de XTTS v2 (no comercial) queda confinada a `clone/`: `src/frances` jamás importa `TTS`, `chatterbox`, `torch` ni `faster_whisper`; el adaptador XTTS exige `COQUI_TOS_AGREED=1`.
- Consentimiento de voces (spec D8): para clonar solo se usan referencias `synthetic` (derivadas de una voz `builtin`) o `consented_recording` con `consent_ref`; si la voz es `teen`/`child` y es grabación, `consent_ref` empieza por `guardian:`. Nunca datasets con menores identificables. `load_voices` es el único punto que lo valida y lanza `ConfigError` (exit 4).
- La clave de caché depende de `tts_norm(text)`, la voz y la familia del motor (no del motor concreto): Edge y Azure producen la misma voz neural y comparten clave (R-15). Todo el SQL de `audio` y `card_audio` vive en `src/frances/audio/repo.py`; `clone/` lo importa, no escribe SQL propio.
- Medidor `azure_tts_chars` con `month = current_month(now)`; tope `settings.audio.azure_tts_monthly_char_cap` (450 000). Formato final único (MP3 mono 24 kHz 48 kbps, −16 LUFS) siempre vía `frances.audio.post.postprocess`. Los errores se registran con `frances.log.redact()` antes de guardarse en `audio.error`; como `redact` no borra hex (R-07), los logs pueden llevar la cache key completa.
- `clone/` (R-16): base liviana sin extras para los tests no-heavy (los corre `clone-tests.yml`, OPS-01); los motores y el Transcriber importan sus extras perezosamente.

## Review Focus

1. Dos tarjetas o materiales con «l’école» y `l'école` deben compartir un único clip: la clave de caché es invariante a la tipografía del apóstrofo, a NFD y a espacios finos, pero distingue voz y familia. Test: AUD-02 `test_cache_key_typography_invariant`.
2. Una grabación de un menor sin consentimiento del tutor nunca llega a clonarse: `teen`/`child` + `consented_recording` sin `consent_ref` que empiece por `guardian:` es `ConfigError`. Test: AUD-01 `test_minor_recording_requires_guardian_consent`.

Clave por familia (spec §6.5, R-15):

```python
payload = {"t": tts_norm(text), "v": voice.id, "f": family, "fv": FAMILY_VERSION[family]}
sha256(json.dumps(payload, sort_keys=True, ensure_ascii=False, separators=(",", ":")).encode()).hexdigest()[:32]
```

Rotación de la voz de `front` (determinista; el cuerpo no lo fijan firma ni tests):

```python
pool = sorted((v for v in voices if v.enabled and v.id not in fixed), key=lambda v: v.id)
start = int(hashlib.sha256(card_id.encode()).hexdigest(), 16) % len(pool)
rot = [pool[(start + i) % len(pool)] for i in range(min(settings.audio.rotating, len(pool)))]
```

Reglas de `voices_for`: `field == "example"` → `[primera voz de fixed_voices habilitada]`; `kind == "drill"` y `front` → todas las habilitadas ordenadas por id; si no → fijas habilitadas (en el orden de `fixed_voices`) + `rot`.
