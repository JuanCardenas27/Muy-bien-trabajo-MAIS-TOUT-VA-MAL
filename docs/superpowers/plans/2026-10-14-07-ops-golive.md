# Operación diaria y puesta en marcha -- Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Lee `AGENTS.md` antes de tomar una tarea.

**Goal:** Que el pipeline corra solo cada mañana a las 05:17 America/Bogota en el repo privado `frances-data`, persista su estado en git, publique el sitio cifrado solo cuando haya algo nuevo, avise con un único issue cuando algo falla, y dejar la puesta en marcha real (GCP, repo de datos, secretos, backfill, runner de clonación) como checklists ejecutables.

**Architecture:** Tres comandos nuevos en `frances.ops` (`run-daily`, `report-failure`, `doctor`) y dos scripts bash (`scripts/persist.sh`, `scripts/runner/install.sh`) que los workflows de `data-repo-template/` encadenan: checkout del repo de datos + checkout del código público en `vars.FRANCES_CODE_SHA` → `restore` → `run-daily` → `persist.sh` → (si cambió algo) build + `bundle` + deploy de Pages → `report-failure` si falló. El repo público solo corre CI y un demo con datos sintéticos.

**Tech Stack:** Python 3.12 + Typer, `subprocess` con argv para `gh`, bash (`set -euo pipefail`), `jq`, GitHub Actions (`actions/checkout`, `astral-sh/setup-uv`, `actions/setup-node`, `actions/upload-pages-artifact`, `actions/deploy-pages`), systemd `--user`, PyYAML + `tomllib` en los tests, shellcheck.

**Spec:** `docs/superpowers/specs/2026-10-14-frances-classroom-design.md` (D1, D2, D11, D12, §5, §6.9, §7, §8, §10)

Plan maestro: docs/superpowers/plans/2026-10-14-00-master-plan.md (Global Constraints y contratos aplican a todas las tareas)

## Restricciones del subsistema

- Toda action de terceros va fijada por SHA de commit de 40 hex con el tag como comentario (`uses: actions/checkout@<sha> # v4.2.2`). El SHA se resuelve al implementar con `gh api repos/<owner>/<action>/commits/<tag> --jq .sha` (resuelve también tags anotados); nunca un tag ni una rama.
- Secretos solo por GitHub Secrets del repo `frances-data`, y solo los de la lista de variables de entorno del plan maestro (más `GITHUB_TOKEN`/`github.token`). Se exponen con `env:` a nivel de **step**, nunca de job ni de workflow, y solo al step que los usa. Nada de `set -x`.
- Los logs del repo de datos no llevan contenido: ni títulos, ni nombres de curso, ni texto, ni mensajes de excepción sin redactar. Los comandos de este plan imprimen nombres de etapa, estados, conteos, hashes y tamaños; todo lo demás pasa por `frances.log.redact()`.
- El repo público nunca ve datos reales: sus workflows (`ci.yml`, `contracts.yml`, `e2e.yml`, `clone-tests.yml`, `demo-pages.yml`) no referencian ningún `secrets.*` y solo publican el demo sintético. `frances-data` nunca hace push al repo público ni abre issues allí.
- Concurrencia compartida: `daily.yml`, `reconcile.yml` y `clone.yml` usan `concurrency: {group: frances-data, cancel-in-progress: false}`; nunca hay dos escritores del repo de datos a la vez. `persist.sh` igual tolera un push concurrente humano (rebase con 3 reintentos).
- Exit codes: los del plan maestro. En los workflows, `2` (parcial) deja el job verde con un `::warning::` y no abre issue (spec §6.9: se reintenta al día siguiente; aceptado en R-25); `1` y `3` abren o comentan el issue y terminan el job con ese código.
- CLI (R-05): cada comando propio declara `data: DataOpt = Path(".")` (FND-04, `frances.cli`), arma el contexto con `make_context(data)` (FND-03, `frances.stage`) y termina con `exit_with(...)`; no hay `--data` global.

1. Una falla de auth no deploya un sitio vacío ni pisa el del día anterior: con exit 3 no se escribe nada, `changed` es `false` y los steps de build/bundle/deploy no corren. Tests: OPS-02 `test_auth_error_stops_pipeline_and_marks_unchanged`, OPS-05 `test_deploy_steps_skip_on_auth_failure`.
